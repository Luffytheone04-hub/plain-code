# RFC-0010 — Plain Expressions

Status: Proposed

Target Version: v1.1.0

Author: Plain Language Team

---

## Goal

This RFC introduces **Plain Expressions**.

The purpose is **not** to make Plain read like English.

The purpose is to make Plain express programming ideas using human concepts instead of JavaScript concepts.

Examples:

Instead of:

    players[0]

Plain should allow:

    first player from players

Instead of:

    user.name

Plain should allow:

    name of user

Instead of exposing arrays, indexes and object property access everywhere, Plain should expose the *intent*.

This RFC does **not** remove existing syntax.

Existing syntax remains fully supported for backward compatibility.

The new syntax becomes the recommended style.

---

# Design Philosophy

Plain is **not English**.

Plain is **not JavaScript**.

Plain is a programming language whose vocabulary should resemble how programmers naturally explain code to another person.

Good:

    add(player to players)

Bad:

    players.push(player)

Good:

    first player from players

Bad:

    players[0]

Good:

    name of user

Bad:

    user.name

---

# New Collection Expressions

## First item

New syntax

    first player from players

Compiles to

    players[0]

---

## Last item

New syntax

    last player from players

Compiles to

    players[players.length - 1]

---

## Numbered item

New syntax

    player one from players
    player two from players
    player three from players
    player four from players

Compiles to

    players[0]
    players[1]
    players[2]
    players[3]

The compiler maps number words internally.

Zero-based indexing is never exposed.

---

## Collection length

New syntax

    players length

Compiles to

    players.length

Examples

    remember total as players length

    if players length is above 10

---

# Object Property Expressions

Property access becomes

    name of user

instead of

    user.name

Examples

    show(name of user)

    remember age as age of player

Nested properties become

    city of address of customer

Compiler output

    customer.address.city

---

Property assignment

    name of user becomes "Ayo"

Compiles to

    user.name = "Ayo"

---

# Collection Operations

Instead of exposing push()

Plain provides

    add(player to players)

Compiles to

    players.push(player)

---

Remove item

    remove(player from players)

Compiles to

    players.splice(...)

Compiler chooses the appropriate implementation.

---

Membership

    players contains player

Compiles to

    players.includes(player)

---

# File Operations

New syntax

    read("users.txt")

Compiles to

    fs.readFileSync(...)

---

    write(data to "users.txt")

Compiles to

    fs.writeFileSync(...)

---

# Deliberately NOT Changed

The following remain exactly as they are.

Reason:

They are already concise and technically clear.

    jsonEncode()

    jsonDecode()

    random()

    uppercase()

    lowercase()

    uuid()

    readFile()

    writeFile()

---

# Parentheses

Parentheses remain part of Plain.

Example

    show(first player from players)

This improves parsing accuracy while remaining readable.

Plain does **not** attempt to remove all symbols.

Symbols help both humans and the compiler.

---

# Arrays

Array literals remain unchanged.

Example

    remember scores as [10, 20, 30]

This RFC does not replace array literal syntax.

---

# Compatibility

All existing syntax remains valid.

Examples

Old

    show(players[0])

New

    show(first player from players)

Both compile to identical JavaScript.

# Success Criteria

Plain code should read closer to how programmers naturally explain code aloud.

The compiler must generate identical JavaScript to the equivalent legacy syntax.

The RFC is complete only when

- every new syntax has documentation
- examples are updated
- website is updated
- all tests pass
- backward compatibility is preserved
