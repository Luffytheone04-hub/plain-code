# Phase 2 - Compiler Stabilization (v0.1)

## Rules (Read First)

- Follow ONLY this task.
- Do NOT implement future language features.
- Do NOT invent new syntax.
- Do NOT change existing syntax.
- Do NOT make assumptions.
- Do NOT improve the language design.
- Do NOT add "helpful" features.
- Every previous test MUST continue passing.
- If something belongs to a future milestone, leave it unimplemented.
- If a refactor changes compiler behaviour, revert the refactor instead of changing the language.

---

# Goal

Make the compiler stable, predictable and easier to maintain.

This phase is about reliability, not features.

Plain v0.1 should become a solid foundation before any new language features are introduced.

---

# Task 1 - Improve Error Messages

Replace generic compiler errors with friendly, descriptive messages.

Examples:

Instead of:

Expected token

Use:

Expected keyword "done" before end of file.

---

Instead of:

Unexpected token

Use:

Unexpected keyword "otherwise".

---

Instead of:

Unknown token

Use:

Unknown keyword "remembr".

Did you mean "remember"?

---

Instead of:

Expected identifier

Use:

Expected a variable name after "remember".

Example:

remember age as 16

Keep every error message clear, educational and beginner-friendly.

---

# Task 2 - Expand Test Coverage

Add tests for invalid syntax and compiler errors.

Include tests for:

- Missing "done"
- Unexpected "otherwise"
- Unknown keyword
- Missing identifier
- Missing value after "as"
- Unterminated string
- Invalid comparison
- Unexpected end of file
- Invalid function declaration
- Invalid function call
- Invalid return statement

Every compiler error should have a corresponding test.

---

# Task 3 - Refactor

Improve the compiler implementation WITHOUT changing behaviour.

Allowed:

- Smaller functions
- Better variable names
- Remove duplicate logic
- Simplify parser code
- Improve project organization

Not allowed:

- New syntax
- New language features
- Behaviour changes
- Breaking backwards compatibility

If a refactor changes behaviour, revert the refactor.

---

# Task 4 - Preserve Backwards Compatibility

Verify that every previous example still compiles and runs correctly.

Required examples:

examples/hello.pln

examples/day2.pln

examples/day3.pln

All previously implemented language features must continue working exactly as before.

---

# Task 5 - Improve CLI Output

Replace minimal CLI output with clearer compilation stages.

Example:

✓ Lexing

✓ Parsing

✓ Building AST

✓ Generating JavaScript

✓ Running

Compilation successful.

If compilation fails, clearly indicate the stage that failed.

Example:

✗ Parsing failed

Expected keyword "done" before end of file.
