# RFC-0009 — Plain v1.0.1
## Runtime & Deployment Experience

---

# Rules (Read First)

This is a stabilization and developer-experience release.

Follow ONLY this RFC.

Do NOT invent new language syntax.

Do NOT modify the grammar.

Do NOT introduce new keywords.

Do NOT change existing behaviour.

Do NOT break backwards compatibility.

Every existing test must continue passing.

The objective is to make Plain production-ready for deployment.

---

# Goal

Make deploying Plain applications as simple as possible.

A user should be able to deploy a Plain project without manually figuring out dependencies or startup behaviour.

---

# Task 1 — Runtime Dependency Manager

Implement runtime dependency management.

Plain already knows which JavaScript package each `use` statement maps to.

Use this information.

Examples:

use express
→ express

use sqlite
→ better-sqlite3

use fs
→ built-in

use path
→ built-in

Built-in modules must never be installed.

External packages must be recognised.

---

# Task 2 — plain start

Add a new CLI command:

plain start

Behaviour:

1. Read plain.json

2. Locate the entry file.

3. Resolve imported Plain files.

4. Check runtime dependencies.

5. Install missing dependencies.

6. Compile.

7. Run the generated JavaScript.

The user should only need:

plain start

---

# Task 3 — Dependency Installation

Before compiling:

Check whether required npm packages exist.

If packages are missing:

Install only the missing packages.

Example output:

Checking dependencies...

✓ express

Installing better-sqlite3...

✓ Dependencies ready

Compilation successful.

Application started.

Do NOT reinstall packages that already exist.

Do NOT install Node built-in modules.

---

# Task 4 — plain install

Improve:

plain install

Behaviour:

Read plain.json.

Determine every dependency required by the project.

Install only missing packages.

Nothing else.

---

# Task 5 — plain doctor

Add:

plain doctor

Example output:

✓ Node.js

✓ npm

✓ Plain CLI

✓ Compiler

✓ Formatter

✓ Runtime

✓ Dependencies

✓ Project configuration

If something is missing:

Show a friendly explanation.

---

# Task 6 — Missing Configuration

If plain.json does not exist:

Display:

No plain.json found.

Run:

plain init

to create one.

If an obvious default entry file exists:

Offer to use it.

Do NOT crash.

---

# Task 7 — Offline Handling

If dependency installation fails because the machine is offline:

Explain which package is missing.

Explain which command the user can run manually.

Do NOT produce stack traces.

---

# Task 8 — Build Behaviour

plain build

must NEVER install packages.

It only compiles.

plain run

must NEVER install packages.

It should explain what dependency is missing.

Only

plain start

and

plain install

may install packages.
